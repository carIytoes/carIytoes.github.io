Wafer Failure Prediction on the SECOM Dataset

Independent project · Built ahead of TSMC internship application
Python scikit-learn Random forest SMOTE Class imbalance

Background

The SECOM dataset is a well-known semiconductor manufacturing dataset: sensor readings collected during the fabrication process, paired with a pass/fail label for each wafer. It's a realistic proxy for the kind of problem an equipment or process engineer actually deals with — hundreds of noisy sensor signals, and a rare but costly failure outcome. I built this project specifically ahead of a TSMC equipment engineer internship application, wanting hands-on experience connecting fab sensor data to an actual predictive model rather than just reading about it.

The Core Challenge: Class Imbalance

Wafer failures are — by design of a working fab — rare relative to passes. That's good for a fab, but it's a classic problem for a classifier: a naive model can get high accuracy just by predicting "pass" every time, while completely failing at the one thing that actually matters, catching failures. Addressing this properly was the central technical problem of the project.

Approach

After cleaning the dataset in Python (handling missing sensor readings and irrelevant/constant features), I applied SMOTE (Synthetic Minority Oversampling Technique) to rebalance the training data by generating synthetic examples of the minority "fail" class, rather than simply duplicating existing failure cases. A random forest classifier was then trained on the rebalanced data — chosen partly for its resistance to overfitting on high-dimensional, noisy sensor data, and partly because feature importances from a random forest are directly interpretable, which matters in a manufacturing context where "why did the model flag this wafer" is often as important as the flag itself.

Results

The end result is a working classification pipeline that takes raw fab sensor data in and returns a pass/fail risk prediction — the kind of tool that, in a real fab setting, would let an equipment engineer flag at-risk lots earlier in the process rather than catching failures only at final test.
